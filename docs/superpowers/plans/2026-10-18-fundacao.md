# Subprojeto 1 — Fundação: Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Caminho ponta a ponta funcionando — login no APK e na web, check-in diário criado offline, sincronizado sem duplicar, upload/download no R2, deploy automático no Coolify e APK baixável de uma release.

**Architecture:** Monorepo com `backend/` (.NET 10 Minimal APIs, EF Core/Npgsql, Identity + JWT) servindo também o build web, e `frontend/` (React + Vite) empacotado como APK pelo Capacitor. O front lê/escreve sempre num SQLite local; um *sync engine* com outbox faz push idempotente e pull incremental por versão global. Arquivos vão direto ao R2 por URL pré-assinada.

**Tech Stack:** .NET 10, EF Core 10 + Npgsql, ASP.NET Identity, JWT Bearer, FluentValidation, Serilog, AWSSDK.S3, xUnit + Testcontainers; React 19, Vite 8, TypeScript 6, TanStack Query, openapi-fetch, react-hook-form + zod, Tailwind 4, Vitest, oxlint; Capacitor (major estável atual — confirmar com Context7 antes da Task 5), `@capacitor-community/sqlite` (+ `jeep-sqlite` na web), `sql.js` (testes), `@capacitor/local-notifications`, `@capacitor/camera`, `@aparajita/capacitor-secure-storage`; Playwright.

**Spec:** `docs/superpowers/specs/2026-10-18-protocoloapp-design.md` (seções 2–8 e 9.1)

**Referência de padrões:** repositório `gabrielLAraujo/fechamento` (`.github/workflows/ci.yml`, `backend/Dockerfile`, `backend/docker-entrypoint.sh`, `backend/Directory.*.props`, `Features/Auth/CriarUsuarioCli.cs`, `infra/devbox/` do PR #14). ## Global Constraints

- Código, nomes de arquivos/tipos/rotas em **inglês**; textos de UI em **português (pt-BR)**.
- **Nenhum dado real** no repositório: fixtures e exemplos fictícios; `.gitignore` bloqueia `*.pdf`, `*.jpg`, `*.jpeg`, `*.png`, `*.heic` fora de `**/fixtures/**` e `frontend/public/**`.
- Commits e PRs **sem marca do Claude** (sem `Co-Authored-By`, sem rodapé). Uma branch por subprojeto (`feat/foundation`); `main` só recebe merge com OK do Gabriel.
- .NET: `global.json` SDK `10.0.100` `rollForward: latestFeature`; `TreatWarningsAsErrors=true`, `Nullable=enable`; versões centralizadas em `Directory.Packages.props` (mesmas versões do Fechamento para os pacotes em comum).
- EF Core: `UseSnakeCaseNamingConvention()`; enums persistidos como texto; migrations via bundle aplicado no `docker-entrypoint.sh` (`MIGRATE_ON_START`, padrão `true`).
- Todas as rotas da API sob `/api`; erros em problem details (RFC 9457); conteúdo de payloads de domínio **nunca** em logs.
- Node 24; `npm run lint` = `tsc -b && oxlint`; `npm test` = `vitest run`.
- Tokens: access JWT **15 min**; refresh **30 dias**, rotativo, armazenado só como hash SHA-256.
- Sync: `client_updated_at` aceito até **now + 5 min**; lote de push máx. **500** mudanças; pull página máx. **500** registros.
- Backoff do sync no cliente: `min(5 s × 2^attempts, 15 min)`; sync roda ao abrir, ao voltar ao primeiro plano, ao ficar online e a cada **60 s** com o app aberto.
- URLs pré-assinadas do R2: upload **10 min**, download **5 min**; tamanho máx. de arquivo **25 MB**.
- Limites do ambiente na nuvem: sem `dotnet` (testes do back só no CI ou no dev box); Claude não altera `.github/workflows/*` — escreve o arquivo em `docs/ci/ci.yml` e o Gabriel copia/commita; migrations e `gen:api` rodam no PC ou no dev box.

## Review Focus

1. **Dois aparelhos criam check-in do mesmo dia** (APK e web offline) → deve resultar em **um** registro, não erro de unicidade nem duplicata. Coberto: id determinístico UUIDv5 da data (Task 6) + teste no servidor (Task 3).
2. **Relógio do celular adiantado** → um `client_updated_at` no futuro ganharia todo LWW para sempre. Esperado: rejeitar > now+5 min com erro claro. Teste na Task 3.
3. **Lote com itens válidos e inválidos misturados** → os válidos aplicam, os inválidos voltam `rejected` com erros, nada derruba o lote inteiro. Teste na Task 3.
4. **Pull concorrente com push** → registro com versão menor commitado depois de um pull já ter avançado `since` seria pulado para sempre. Esperado: nenhum registro perdido. Mitigação: `pg_advisory_xact_lock` no push (um usuário, custo nulo) + teste na Task 3.
5. **Refresh token reutilizado** (vazado ou corrida entre dois requests) → esperado: segundo uso falha com 401 e revoga a família inteira. Teste na Task 2.

Também verificado: app morto no meio do sync (outbox só é limpo após resposta `applied`/`stale` — Task 6); token expirado durante sync (refresh automático uma vez — Task 5).
