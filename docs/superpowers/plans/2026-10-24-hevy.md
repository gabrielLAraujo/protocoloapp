# Sincronização com o Hevy — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Importar os treinos do Hevy (chave do usuário, cifrada no servidor) como sessões encerradas, a cada 30 min e sob demanda, com mapeamento de exercícios, confirmação dos pendentes e aviso de duplicado no Histórico.

**Architecture:**
- Feature nova `backend/src/ProtocoloApp.Api/Features/Integrations/` em três partes:
  - `Hevy/`: cliente HTTP tolerante, importador, agendador e endpoints;
  - `Secrets/`: proteção AES-GCM;
  - `Matching/`: port exato de `exerciseMatch.ts` com o dicionário embutido.
- O importador grava `workout_session`/`set_log`/`exercise`/`adherence_log` com `SyncWrites`, numa transação por treino. Os aparelhos recebem tudo pelo pull.
- Estado da conexão e ligações de exercício só por REST (não são entidades sincronizadas).
- Front:
  - migration local v10 (`source`, `external_title`, `rpe`);
  - páginas `/configuracoes/hevy` e `/configuracoes/hevy/exercicios`;
  - selo, aviso de duplicado e modo só leitura no Histórico.

**Tech Stack:** .NET 10, EF Core/Npgsql, `System.Security.Cryptography.AesGcm`, `IHttpClientFactory`, `BackgroundService`/`PeriodicTimer`; React 19, SQLite local, openapi-fetch, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-24-hevy-design.md`

## Global Constraints
- **Regras do `CLAUDE.md`:**
  - código, rotas e nomes em inglês; UI em pt-BR;
  - **nenhum dado real**: nem chave do Hevy real, nem treino real; fixtures fictícias, chaves no formato `test-key-0000-0000-0000-000000000001`;
  - commits do autor configurado (Gabriel), **sem marca do Claude** (sem `Co-Authored-By`, sem rodapé);
  - branch `feat/hevy`; merge em `main` só com OK do Gabriel.
- **Logs:** a chave do Hevy nunca entra em log, exceção, problem details ou resposta. O cabeçalho `api-key` é redigido (`RedactLoggedHeaders`). Do Hevy só se loga contagem, status HTTP e `ex.GetType().Name`; títulos, notas e cargas nunca.
- **Criptografia:**
  - `Integrations__EncryptionKey` = 32 bytes em base64 (seção `Integrations:EncryptionKey`);
  - ausente ou inválida → app sobe, `serverConfigured: false`, `PUT`/`sync` → 503 "Integração com o Hevy não configurada no servidor.", agendador ocioso;
  - formato `0x01 | nonce(12) | cipher | tag(16)`, AAD = `"hevy:" + userId`.
- **Hevy:**
  - base `https://api.hevyapp.com/` (opção `Hevy:BaseUrl`; `http` aceito só para host loopback, para o stub do E2E), cabeçalho `api-key`;
  - `pageSize` 10 para treinos e eventos, 100 para templates; teto de 50 páginas por execução; 300 ms entre páginas;
  - timeout de 20 s, sem redirect, resposta de até 2 MB;
  - `Hevy:Enabled` (padrão `true`; `false` nos testes) e `Hevy:IntervalMinutes` (padrão 30).
- **Datas:** data local da sessão = `start_time` convertido por `IZoneProvider` (America/Sao_Paulo). Primeira sincronização: `sync_from` = `period_start` do ciclo não enviado mais recente; sem ciclo, hoje − 30. O cursor avança só em execução sem erro e vale início da execução − 5 min.
- **Mapeamento de séries:**
  - `normal`/`failure` → `normal`; `warmup` → `warmup`;
  - `dropset` → `drop` (pai = última série principal do exercício, mesmo `set_index`; sem pai → `normal`);
  - `weight_kg` nulo → 0;
  - pular (e contar em `skippedSets`): `reps` nulo, `reps > 200`, `weight_kg > 1000`, índice > 50;
  - `rpe` fora de 1..10 → nulo.
- **Migrations:**
  - EF só pelo Codegen: um commit com `[migration:HevySync]` (Task 4, a única migration EF), depois `git pull` do commit do bot;
  - mudança de endpoint: `[codegen]`, depois `npm run gen:api`;
  - migration local SQLite: **versão 10** (Task 8, a única).
- **Testes:**
  - unitários: `cd backend && dotnet test tests/ProtocoloApp.UnitTests`;
  - integração (Testcontainers): só no CI ou no dev box; acompanhar com `gh api`;
  - front: `npm run lint && npm test`.
- **Visual:** só `src/ui` (`Card`, `Chip`, `ListRow`, `Sheet`, `Button`, `ui/styles.ts`), alvos de 44 px.

### Contrato (fixo; tasks paralelas dependem dele)
- **Payload `workout_session`:** + `source: "app"|"hevy"` (pull; push ignora) e `external_title: string|null` (pull; push ignora).
- **Payload `set_log`:** + `rpe: number|null` (opcional, 1..10, múltiplo de 0,5; push e pull).
- **REST (camelCase, sob `/api/integrations/hevy`):**
  - `GET ""` → `HevyStatusResponse { serverConfigured: bool, connected: bool, keyLast4: string|null, syncFrom: date|null, lastAttemptAt, lastSuccessAt: datetime|null, lastError: "unauthorized"|"rate_limited"|"unavailable"|"format"|"key_unreadable"|null, lastResult: HevySyncResult|null, running: bool, pendingExercises: int }`.
  - `PUT ""` `{ apiKey: string (1..200, trim), syncFrom?: date }` → 200 `HevyStatusResponse`. Erros: 422 (`apiKey` "O Hevy recusou a chave. Confira a chave e se a conta é Pro."), 502 (Hevy indisponível: "Não foi possível falar com o Hevy agora. Tente de novo."), 503 (não configurado).
  - `PATCH ""` `{ syncFrom: date }` → 200 (zera cursor); 404 sem conexão.
  - `DELETE ""` → 204.
  - `POST "/sync"` → 200 `HevySyncResult { imported, updated, deleted, unchanged, skippedNoPlan, skippedSets, pendingExercises }`. Erros: 409 "Sincronização já em andamento.", 404 sem conexão, 503 não configurado, 502 com `lastError` no problem.
  - `GET "/exercises?all=false"` → `HevyExerciseLinkResponse[] { id, templateId, title, exerciseId, exerciseName, status: "auto"|"pending"|"confirmed", setCount }`.
  - `PUT "/exercises/{id:guid}"` `{ exerciseId: guid|null }` → 200 `HevyExerciseLinkResponse` (null = manter o provisório). 404 para ligação ou exercício alheio ou apagado.

## Review Focus
1. **`Integrations__EncryptionKey` ausente, curta ou com base64 inválido:**
   - o host sobe e `/health` fica 200;
   - `GET` diz `serverConfigured: false`;
   - nada é logado com o valor (Task 1 e Task 5).
2. **Mesmo treino reprocessado** (evento repetido, cursor com folga, "Sincronizar agora" logo após o agendador):
   - não duplica sessão nem séries nem marca de adesão;
   - `updated_at` igual → `unchanged` (Task 6).
3. **Sessão Hevy apagada no app** ("manter só um") e depois editada no Hevy: não ressuscita, e a marca de treino do dia segue a outra sessão (Task 6).
4. **JSON do Hevy com campos extras, nulos, `exercises` ausente ou série só de duração:**
   - importa o resto e conta o pulado;
   - envelope sem a lista → erro `format`, cursor parado (Tasks 2 e 6).
5. **Treino às 23h30 de São Paulo (02h30 UTC do dia seguinte):** a sessão fica na data local, e a ficha é a ativa naquela data local (Task 6).
